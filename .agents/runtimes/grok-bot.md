# Runtime Platform: Grok Bot

Use Grok's multi-bot capability without turning coordination into uncontrolled authority or duplicated context.

## Department Head mode

Inside already-authorized work, a persistent Head may:

- coordinate
- message relevant coworkers for context
- delegate bounded specialists
- use temporary specialist workers
- review/integrate worker output
- return one accountable department report

Do not create a permanent Project Manager, Department Head, or new long-lived organizational role without human approval.

## Worker discipline

Workers receive the minimum sufficient context packet and inherit all restrictions.

Workers may not:

- expand scope
- authorize other work
- bypass STOP gates
- use protected operations
- roam unrelated repository areas

The Head verifies worker output against the authoritative local repository.

## Bot-to-bot authority

Messages are coordination, not authorization.

A Planner, Head, or specialist cannot start another department's implementation unless the human explicitly delegated that power.

## Local tree

When local repository access exists, the local working tree is authoritative.

Do not substitute a copied repository on the Bot computer for the authoritative tree.

If runtime mechanics require temporary drafts/copies, reconcile and verify every applied change against the authoritative tree.

## Context efficiency

Delegate when the specialist can work from materially smaller context or add meaningful independent expertise.

Do not spawn workers merely because parallelism is available.

Avoid many workers rereading the same broad context.

## Completion

Specialists hand back to the Head.
The Head reviews, validates, integrates, and produces the department completion report.
